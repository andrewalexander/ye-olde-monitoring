1. The counter

You are visitor number

<script src="/counter.js" data-site="local-test"></script>

How it works: that one script tag is all a site needs. counter.js adds an <img src="/counter.svg?site=local-test"> where the tag sits. Each load of that image adds 1 to the local-test counter and stores a hit with source counter.

Limits: each IP gets 30 counts a minute. Past that the image still shows, but the number stops going up, so holding down reload won't inflate it. site must match [A-Za-z0-9._-], up to 64 characters.

2. Reading it without counting

Plain number from /counter.txt?site=local-test&noinc=1: …

Add noinc=1 to show the number somewhere without counting a visit. Without it, counter.txt counts too, the same as the image. Pressing refresh should leave the number unchanged.

3. Make some hits

Each link below shows up in the table in section 4. The source column says which path recorded it.

  • reload this page: the counter goes up by 1 (source counter). Caddy also logs the page, counter.js and counter.svg requests (source caddy).
  • a 404: Caddy logs it with status 404. That's how you'd spot scanners probing for /wp-login.php and similar paths.
  • a page with a query string: the query is stored separately from the path.
  • count a different site: each site has its own counter. Compare report hits -top site.
  • the example Go app (port 8001): it doesn't go through Caddy. middleware.Wrap records each request and posts it in batches to /ingest with a bearer token (source middleware, site example).

  • You should see ten 401s, then 429. After 10 bad requests in a minute, the ingest circuit breaker blocks your IP for a cooldown. One trip row is saved with everything known about you: headers (secrets hashed), body samples, the request rate and reverse DNS. See report trips, then report trip <id>. Press it again while cooling down and you get only 429s.

source
counter: counted by dnscount serve. caddy: read from Caddy's JSON access log. middleware: sent by a Go app.
site
The counter's site= value, the middleware's Options.Site, or for Caddy the request host (localhost here).
client
The visitor's IP. Caddy sits in front, so dnscount takes it from X-Forwarded-For, but only because the request came from a trusted proxy (-trusted-proxies). Here it's your Mac as Docker sees it, usually the network gateway.

Every endpoint, public and admin, is described in plain text at localhost:8081/api.

The admin API has no auth. In production it only listens on localhost (reach it with an SSH tunnel). The :8081 Caddy listener this page uses exists only in the local Caddyfile.

5. Going further

docker compose exec dnscount dnscount report hits -top ip -since 1h
docker compose exec dnscount dnscount report hits -top path
docker compose exec dnscount dnscount report hits -ip <client from the table>
docker compose exec dnscount dnscount report trips
docker compose exec dnscount dnscount check        # data sanity checks
curl -s localhost:8081/api                         # plain-text reference for every endpoint
curl -s localhost:8081/api/health                  # breaker state + check results
make down                                          # stop and wipe the local data
