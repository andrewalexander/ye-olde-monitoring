1. The counter

You are visitor number

<img src="/counter.svg?site=localhost">

How it works: the image only reads. Loading this page put a line in Caddy's access log, the tailer turned that line into a hit, and the counter is one visitor per client IP per UTC day that loaded a page of the site (a GET with status 2xx or 304 for /, */, *.html or a path with no extension). Assets, 404s, POSTs and the counter image itself don't count, and it doesn't matter which source recorded the visit or whether two did.

Which sites: only those in serve -counter-sites (here localhost,caddy-site,example). Any other site= gets a 404. The number is cached for -counter-ttl (2s here, 1m by default). Reloading won't change it, because you're already today's visitor from your IP.

2. The same number as text

/counter.txt?site=localhost: …

Compare examples/caddy-site on port 8002: static files only, the way a real static site is built. Its log lines are renamed caddy-site, so it has its own counter.

3. Make some hits

Each link below shows up in the table in section 4. The source column says which path recorded it.

  • reload this page: Caddy logs the page and the counter.svg request (source caddy). The counter stays the same, because you've already been counted today.
  • a 404: Caddy logs it with status 404. That's how you'd spot scanners probing for /wp-login.php and similar paths.
  • a page with a query string: the query is stored separately from the path.
  • a site not in -counter-sites: 404. Compare report hits -top site.
  • the example Go app (port 8001): it doesn't go through Caddy. middleware.Wrap records each request and posts it in batches to /ingest with a bearer token (source middleware, site example).

  • You should see ten 401s, then 429. After 10 bad requests in a minute, the ingest circuit breaker blocks your IP for a cooldown. One trip row is saved with everything known about you: headers (secrets hashed), body samples, the request rate and reverse DNS. See report trips, then report trip <id>. Press it again while cooling down and you get only 429s.

caddy: read from Caddy's JSON access log. middleware: sent by a Go app.
site
The counter's site= value, the middleware's Options.Site, or for Caddy the request host (localhost here).
client
The visitor's IP. Caddy sits in front, so dnscount takes it from X-Forwarded-For, but only because the request came from a trusted proxy (-trusted-proxies). Here it's your Mac as Docker sees it, usually the network gateway.

The full table explorer is at localhost:8090, and its endpoints are described in plain text at localhost:8090/api.

The explorer has no auth. In production it's reachable only from the LAN. The :8090 Caddy listener this page uses exists only in the local Caddyfile.
