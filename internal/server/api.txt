dnscount serve API
==================

Two listeners:

  PUBLIC  dnscount serve -addr        (default :8080; usually behind Caddy)
          counter + /ingest. Safe to expose.
  ADMIN   dnscount serve -admin-addr  (default 127.0.0.1:8081)
          GET /api/health only: the live breaker stats, which only this
          process has. NO AUTH: keep it on localhost.

This page: GET /api on the admin listener. Everything recorded (hits, DNS,
alerts, bans, trips) is read from the explorer: dnscount explore, GET /api
there.

Errors are a plain-text body: 400 = bad parameter, 404 = no such thing,
500 = server error.


PUBLIC
======

GET /counter.svg?site=NAME
  The visitor counter image (image/svg+xml). It only reads: the number is
  computed from recorded hits, one per client IP per UTC day that loaded a
  page of NAME (a GET answered 2xx or 304 for "/", "*/", "*.html" or a path
  with no extension). Assets, errors, POSTs and the counter image itself
  don't count, and a visit recorded twice (by Caddy's log and by
  middleware, say) is still one visitor. Put it on a page with
    <img src="/counter.svg?site=NAME" alt="visitor counter">
  and proxy /counter.* to this listener (deploy/Caddyfile.example).
  The number is reused for -counter-ttl (default 1m) before it's recomputed.
  404 unless NAME is in -counter-sites.

GET /counter.txt?site=NAME
  The same number as text/plain.

POST /ingest
  Where Go apps send hits (middleware.NewRemoteSink does this for you).
  Auth:   Authorization: Bearer <token>   (-token or $DNSCOUNT_TOKEN;
          no token configured = everything is rejected)
  Body:   JSON, max 1 MB, max 1000 hits. Unknown fields are an error.
    {"hits": [{
      "ts":         "2026-10-27T18:00:00Z",  required; not before 2000,
                                             at most 5 minutes in the future
      "site":       "blog",                  required
      "client_ip":  "203.0.113.9",           required, a valid IP
      "source":     "middleware",
      "method":     "GET",
      "host":       "blog.example.com",
      "path":       "/post/1",
      "query":      "ref=x",
      "status":     200,                     0 or 100-599
      "bytes":      1234,
      "user_agent": "...",
      "referer":    "...",
      "forwarded_for": "...",
      "id":         "...",                   optional dedup key; a repeated id
                                             is a duplicate, not a new hit
    }]}
  Answers:
    200  {"accepted": N, "duplicates": M}
    400  bad JSON, too many hits, or any invalid hit. The whole batch is
         rejected and nothing is stored; the body lists what was wrong.
    401  missing or wrong token
    405  not a POST
    413  body over 1 MB
    429  this IP tripped the breaker (600 requests or 10 bad ones in a
         minute). Retry-After says how many seconds until the cooldown
         (5 minutes) ends. Each trip is recorded: see the
         explorer's /api/trips.


ADMIN
=====

GET /api/health
  The /ingest breaker, and the data sanity checks (cached 10
  minutes: they scan whole tables). The syslog breakers live in the
  dnscount syslog process and are logged there.
  {"breakers": [{"name","trips","suppressed","tripped_now","keys"}],
   "data_problems": null or ["..."]}
